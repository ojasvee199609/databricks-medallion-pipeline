# Data Model

Entity and schema reference for the **databricks-medallion-pipeline** project.
Covers source CSVs and Delta tables across Bronze, Silver, and Gold layers.

For quality rules see `data-quality-strategy.md`. For pipeline design see
`design-notes.md`.

---

## Overview

The pipeline models a simple e-commerce domain: **customers** place **orders**
for **products**. Three source CSV files land in Databricks volumes, are ingested
into Bronze Delta tables, enriched with quality flags in Silver, and aggregated
into Gold tables for dashboard consumption.

### Entity relationship (logical)

```text
┌─────────────────┐         ┌─────────────────┐
│    customers    │         │    products     │
│  PK: customer_id│         │  PK: product_id │
└────────┬────────┘         └────────┬────────┘
         │                           │
         │ 1                         │ 1
         │                           │
         │ N                         │ N
         └──────────┬────────────────┘
                    │
              ┌─────▼─────┐
              │   orders  │
              │ PK: order_id
              │ FK: customer_id → customers.customer_id
              │ FK: product_id  → products.product_id
              └───────────┘
```

### Layer summary

| Layer | Tables | Physical type strategy | Grain |
|-------|--------|------------------------|-------|
| Source CSV | `customers`, `orders`, `products` | Text in CSV; logical types below | One row per entity |
| Bronze | `bronze_customers`, `bronze_orders`, `bronze_products` | All `STRING` + ingestion metadata | Same as source |
| Silver | `silver_customers`, `silver_orders`, `silver_products` | Bronze columns + quality flag columns | Same as Bronze (no row loss) |
| Gold | `gold_sales_by_product`, `gold_revenue_by_customer`, `gold_customer_segmentation` | Typed aggregates (`DECIMAL`, `INT`) | Product / customer / segment |

## Source Files (CSV)

Generated by `src/data_generation/generate_sample_data.py` and written to
`data/` locally or `/Volumes/.../medalion/to_process/` on Databricks.

### customers.csv

| Column | Logical type | Nullable | Constraints / values |
|--------|--------------|----------|----------------------|
| customer_id | INT | No | Primary key (sequential 1…N) |
| customer_name | STRING | No | Synthetic name |
| email | STRING | Yes | Required for Silver completeness |
| country | STRING | No | |
| signup_date | DATE | No | `YYYY-MM-DD` |
| customer_segment | STRING | No | `Premium`, `Standard`, `Basic` |
| lifetime_value | DECIMAL(2dp) | No | Non-negative |

**Volume:** ~10,000 clean rows + 10 duplicate-row appends + 50 NULL emails → **10,010 rows**.

### products.csv

| Column | Logical type | Nullable | Constraints / values |
|--------|--------------|----------|----------------------|
| product_id | INT | No | Primary key (sequential 1…N) |
| product_name | STRING | No | |
| category | STRING | No | e.g. Electronics, Clothing |
| price | DECIMAL(2dp) | No | Always ≥ cost |
| cost | DECIMAL(2dp) | No | |
| stock_quantity | INT | No | Non-negative |
| reorder_level | INT | No | Non-negative |

**Volume:** **500 rows** (no injected defects).

### orders.csv

| Column | Logical type | Nullable | Constraints / values |
|--------|--------------|----------|----------------------|
| order_id | INT | No | Primary key |
| customer_id | INT | Yes | FK → `customers.customer_id` |
| order_date | DATE | No | |
| product_id | INT | Yes | FK → `products.product_id` |
| quantity | INT | No | Positive |
| unit_price | DECIMAL(2dp) | No | Matches product price at order time |
| total_amount | DECIMAL(2dp) | No | `quantity × unit_price` |
| order_status | STRING | No | `Pending`, `Completed`, `Cancelled` |
| payment_date | DATE | Yes | NULL when status is Pending or Cancelled |

**Volume:** ~100,000 clean rows + 20 duplicate-row appends + injected FK/null issues → **100,020 rows**.

### Filename convention

Timestamped batches: `customers_YYYYMMDD_HHMMSS.csv`, `orders_…`, `products_…`.
Bronze ingestion also accepts non-timestamped names (`customers.csv`, etc.).

## Bronze Layer

**Purpose:** Raw landing zone. Preserve source values exactly (including defects).

**Tables:** `bronze_customers`, `bronze_orders`, `bronze_products`

**Storage:** Delta Lake at `{BRONZE_BASE_PATH}/{table_name}` (managed tables on Databricks).

### Schema — all business columns

Every source column is stored as **`STRING`** (`nullable=True`) per
`bronze_config.py` explicit `StructType`. Logical types are validated in Silver.

#### bronze_customers / bronze_orders / bronze_products

| Column group | Columns |
|--------------|---------|
| customers | `customer_id`, `customer_name`, `email`, `country`, `signup_date`, `customer_segment`, `lifetime_value` |
| products | `product_id`, `product_name`, `category`, `price`, `cost`, `stock_quantity`, `reorder_level` |
| orders | `order_id`, `customer_id`, `order_date`, `product_id`, `quantity`, `unit_price`, `total_amount`, `order_status`, `payment_date` |

### Bronze metadata columns (all tables)

| Column | Type | Description |
|--------|------|-------------|
| `_ingested_at` | TIMESTAMP | UTC ingestion timestamp |
| `_source_file` | STRING | Source CSV filename |

### Row counts (validated sample run)

| Table | Rows |
|-------|-----:|
| bronze_customers | 10,010 |
| bronze_products | 500 |
| bronze_orders | 100,020 |

## Silver Layer

**Purpose:** Row-level data quality validation. Every Bronze row is retained;
bad rows receive flag columns instead of being removed.

**Tables:** `silver_customers`, `silver_orders`, `silver_products`

**Storage:** Delta Lake at `{SILVER_BASE_PATH}/{table_name}`.

### Base columns

All Bronze business columns and metadata (`_ingested_at`, `_source_file`) are
carried forward unchanged.

### Quality flag columns

Each applicable check adds two columns. N/A checks use `passed = true`, `details = ""`.

| Check | Column pattern | Type |
|-------|----------------|------|
| Completeness | `completeness_check_passed`, `completeness_check_details` | BOOLEAN, STRING |
| Uniqueness | `uniqueness_check_passed`, `uniqueness_check_details` | BOOLEAN, STRING |
| Type validation | `type_validation_passed`, `type_validation_details` | BOOLEAN, STRING |
| Referential integrity | `referential_integrity_passed`, `referential_integrity_details` | BOOLEAN, STRING |

### Combined outcome

| Column | Type | Values |
|--------|------|--------|
| `quality_check_result` | STRING | `PASS` — all applicable checks passed; `FAIL` — one or more failed |

### Checks applied per table

| Table | Completeness fields | Uniqueness key | Type validation | Referential integrity |
|-------|--------------------|----------------|-----------------|----------------------|
| silver_customers | `email` | `customer_id` | ✓ | — |
| silver_orders | `customer_id`, `product_id` | `order_id` | ✓ | `customer_id`, `product_id` |
| silver_products | — | — | ✓ | — |

### Logical type rules (Silver type validation)

Validated on string Bronze values before Gold casting:

| Entity | Fields validated |
|--------|------------------|
| customers | `customer_id` (int), `lifetime_value` (decimal), `signup_date` (date), `customer_segment` (enum) |
| products | `product_id`, `price`, `cost`, `stock_quantity`, `reorder_level` |
| orders | `order_id`, `customer_id`, `product_id`, `quantity`, `unit_price`, `total_amount`, `order_date`, `order_status`, `payment_date` |

### Row counts

Silver row counts **must equal** Bronze (10,010 / 500 / 100,020).

## Gold Layer

**Purpose:** Business-ready analytics tables. Only **Silver orders with
`quality_check_result = 'PASS'`** contribute to order counts and revenue.
Customer dimension uses deduplicated `customer_id` (one row per key).

**Tables:** `gold_sales_by_product`, `gold_revenue_by_customer`, `gold_customer_segmentation`

**Storage:** Delta Lake at `{GOLD_BASE_PATH}/{table_name}`.

### gold_sales_by_product

**Grain:** One row per product (all 500 products retained; zero-order products show 0).

| Column | Type | Description |
|--------|------|-------------|
| product_id | STRING | Product primary key |
| product_name | STRING | From silver_products |
| category | STRING | Product category |
| total_orders | BIGINT | Count of PASS orders for this product |
| total_revenue | DECIMAL(18,2) | Sum of `total_amount` for PASS orders |
| avg_order_value | DECIMAL(18,2) | `total_revenue / total_orders` (0 if no orders) |

**Source SQL:** `src/gold/01_sales_by_product.sql`

---

### gold_revenue_by_customer

**Grain:** One row per unique `customer_id` (deduped from Silver; ~10,000 customers).

| Column | Type | Description |
|--------|------|-------------|
| customer_id | STRING | Customer primary key |
| customer_name | STRING | From deduplicated silver_customers |
| customer_segment | STRING | Source segment: Premium / Standard / Basic |
| total_orders | BIGINT | Count of PASS orders for this customer |
| total_revenue | DECIMAL(18,2) | Sum of `total_amount` for PASS orders |
| avg_order_value | DECIMAL(18,2) | `total_revenue / total_orders` (0 if no orders) |
| lifetime_value_actual | DECIMAL(18,2) | Computed revenue from orders (not source `lifetime_value`) |

**Source SQL:** `src/gold/02_revenue_by_customer.sql`

**Note:** `lifetime_value` from the source customer record is **not** used in Gold
metrics; `lifetime_value_actual` reflects observed order revenue.

---

### gold_customer_segmentation

**Grain:** One row per behavioral **segment_type** (4 rows).

| Column | Type | Description |
|--------|------|-------------|
| segment_type | STRING | `High-Value`, `Repeat`, `One-Time`, `Inactive` |
| customer_count | BIGINT | Customers in this segment |
| avg_revenue | DECIMAL(18,2) | Mean `total_revenue` per customer in segment |
| total_revenue | DECIMAL(18,2) | Sum of customer revenues in segment |

**Segmentation rules** (based on PASS orders only):

| segment_type | Rule |
|--------------|------|
| Inactive | 0 PASS orders |
| High-Value | Top 20% by revenue among customers with ≥1 PASS order (`NTILE(5) = 1`) |
| Repeat | ≥2 PASS orders, not High-Value |
| One-Time | Exactly 1 PASS order, not High-Value |

**Source SQL:** `src/gold/04_customer_segmentation.sql`

**Distinction:** `customer_segment` (Premium/Standard/Basic) is a **source
attribute** on customers. `segment_type` is a **behavioral** label derived from
order history in Gold.

## Keys and Relationships

### Primary keys

| Entity | Key | Enforced in |
|--------|-----|-------------|
| Customer | `customer_id` | Silver uniqueness check (flag only) |
| Product | `product_id` | Implicit in clean generated data |
| Order | `order_id` | Silver uniqueness check (flag only) |

Bronze does **not** enforce uniqueness or referential integrity — defects are
preserved for Silver to detect.

### Foreign keys

| Child | Column | Parent | Parent column |
|-------|--------|--------|---------------|
| orders | `customer_id` | customers | `customer_id` |
| orders | `product_id` | products | `product_id` |

Silver referential integrity flags orphan non-NULL FKs. NULL FKs are handled by
the completeness check.

### Gold join paths

```text
silver_products  ──LEFT JOIN──►  PASS silver_orders  ──►  gold_sales_by_product
silver_customers ──LEFT JOIN──►  PASS silver_orders  ──►  gold_revenue_by_customer
silver_customers + PASS orders ──►  gold_customer_segmentation
```

## Type Evolution Across Layers

| Layer | Typing approach | Rationale |
|-------|-----------------|-----------|
| CSV | Text representation of typed values | Portable file format |
| Bronze | All `STRING` | Preserve raw anomalies (NULL, bad formats, orphans) |
| Silver | Still `STRING` for business columns; BOOLEAN/STRING for flags | Validate without casting away problems |
| Gold | `DECIMAL(18,2)`, `BIGINT` for metrics | Analytics-ready aggregates |

Gold SQL casts `total_amount` at query time:
`CAST(o.total_amount AS DECIMAL(18, 2))`.

`src/dashboard/dashboard_queries.sql` reads Gold tables only:

| Visualization | Gold table | Key columns |
|---------------|------------|-------------|
| Bar chart (top 10 products) | `gold_sales_by_product` | `product_name`, `total_revenue` |

| Pie chart (segmentation) | `gold_customer_segmentation` | `segment_type`, `customer_count` |
